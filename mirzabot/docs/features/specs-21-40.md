# Specs F21–F40 — ۲۰ قابلیت جدید (طراحی‌شده برای این کدبیس)

فرمت هر اسپک: **هدف / دیتابیس / فایل‌ها / جریان / اولویت-ریسک**.

---

## F21 — Sub-link یکپارچه (Subscription Aggregator)
- **هدف:** یک لینک ساب واحد که همه کانفیگ‌های کاربر را خودکار به‌روزرسانی می‌کند (تلگرام/Sing-box/Clash) — جایگزین لینک‌های جداگانه.
- **دیتابیس:** `user.sub_token` (ستون جدید، تصادفی) — `sub/index.php` موجود را با توکن کاربر به‌جای `id_invoice` گسترش دهید.
- **فایل‌ها:** `sub/index.php` (توسعه — جستجو با `sub_token` + خروجی multi-config)، `function.php` (ساخت توکن هنگام ثبت‌نام).
- **جریان:** کاربر در منو «لینک اشتراک من» یک لینک `domain/sub/t-XXXX` می‌گیرد ← هر بار باز شدن، همه سرویس‌های فعالش را با هم برمی‌گرداند.
- **اولویت:** 🥇 | **ریسک:** متوسط — توکن را با `random_bytes` بسازید، نه `id_invoice` قابل حدس.

## F22 — کد گیفت/ریدمپشن دسته‌جمعی
- **هدف:** تولید دسته‌جمعی کدهای گیفت با مبلغ دلخواه + خروجی CSV برای فروش حضوری.
- **دیتابیس:** `gift_codes` (جدول جدید: code, value, status, created_by, used_by, used_at).
- **فایل‌ها:** `admin.php` (فرم «ساخت N کد × مبلغ»)، `api/export.php` (خروجی CSV)، `index.php` (هندلر `redeem_` با `creditBalance` + یکبارمصرف).
- **جریان:** ادمین ۱۰۰ کد ۵۰هزار تومانی می‌سازد ← CSV می‌گیرد ← کاربر کد را در ربات می‌زند ← موجودی شارژ می‌شود.
- **اولویت:** 🥇 | **ریسک:** کم — جدول `Giftcodeconsumed` موجود الگوی خوبی است.

## F23 — خرید اقساطی
- **هدف:** پیش‌پرداخت + اقساط؛ سرویس فعال می‌ماند تا اقساط عقب بیفتد، سپس قفل می‌شود.
- **دیتابیس:** `installments` (جدول جدید: order, user, total, paid, status, due_dates) + `invoice.installment_id`.
- **فایل‌ها:** `index.php` (انتخاب «اقساط» در پرداخت)، `cronbot/installment_check.php` (جدید — بررسی سررسید)، `admin.php` (مدیریت).
- **جریان:** خرید اقساطی ← سرویس ساخته می‌شود با `Status=installment` ← هر سررسید از موجودی/درگاه کسر می‌شود ← ۲ قسط عقب‌افتاده = disable با `ManagePanel->ExpireUser`.
- **اولویت:** 🥈 | **ریسک:** بالا (پول) — فقط با `settleOrderOnce`-like mutex برای هر قسط.

## F24 — تخفیف فلش زمان‌دار
- **هدف:** تخفیف محدود به بازه زمانی با شمارش معکوس در کیبورد.
- **دیتابیس:** `flash_deals` (جدول جدید: product, discount_pct, starts_at, ends_at).
- **فایل‌ها:** `function.php` (تابع `flashDiscountFor($product)` در `KeyboardProduct`/قیمت‌گذاری)، `keyboard.php` (نمایش).
- **جریان:** ادمین دیل می‌سازد ← قیمت‌ها در بازه خودکار کم می‌شوند ← بعد از پایان بازگشت.
- **اولویت:** 🥈 | **ریسک:** کم.

## F25 — قیمت‌گذاری پویا بر اساس بار پنل
- **هدف:** قیمت سرویس روی پنل پر، کمی بالاتر (یا برعکس) تا بار توزیع شود.
- **دیتابیس:** `marzban_panel.load_factor` (ستون جدید).
- **فایل‌ها:** `function.php` (ضریب در محاسبه `price_product`)، `panels.php`.
- **جریان:** `pickPanel` (F17) پنل کم‌بار را انتخاب می‌کند؛ اگر همه پر بودند، ضریب اعمال می‌شود.
- **اولویت:** 🥉 | **ریسک:** متوسط.

## F26 — انتقال کیف‌پول (P2P)
- **هدف:** کاربران بتوانند موجودی را با کد امن به هم منتقل کنند.
- **دیتابیس:** `p2p_transfers` (جدول جدید: from, to, code, amount, status).
- **فایل‌ها:** `index.php` (هندلر `p2p_`)، `function.php` — انتقال فقط با `debitBalanceIfSufficient` + `creditBalance` داخل `withTransaction`.
- **جریان:** کاربر A مبلغ و کد می‌سازد ← کد را برای B می‌فرستد ← B کد را وارد می‌کند ← انتقال اتمیک.
- **اولویت:** 🥈 | **ریسک:** بالا — بدون `withTransaction` پیاده نکنید.

## F27 — دستورات اسلش تلگرام
- **هدف:** میانبرهای `/buy`، `/status`، `/invite`، `/help` به‌جای پیمایش منو.
- **دیتابیس:** بدون تغییر.
- **فایل‌ها:** `index.php` (در ابتدای هندلر `$text`، نگاشت اسلش به مسیرهای موجود)، `botapi.php` (دکمه منو با `setMyCommands`).
- **جریان:** کاربر `/status` می‌زند ← همان هندلر موجود وضعیت صدا زده می‌شود.
- **اولویت:** 🥈 | **ریسک:** کم.

## F28 — پیگیری خودکار Trial→خرید
- **هدف:** بعد از اتمام Trial، دنباله پیام‌های نرم (روز ۱/۳/۷) با پیشنهاد تخفیف.
- **دیتابیس:** `trial_users.followup_step` (ستون جدید).
- **فایل‌ها:** `cronbot/trial_followup.php` (جدید).
- **جریان:** کرون هر روز Trialهای تمام‌شده را می‌بیند ← پیام مرحله‌ای + دکمه خرید با کد تخفیف F03.
- **اولویت:** 🥈 | **ریسک:** کم.

## F29 — سلامت کانفیگ + ترمیم خودکار
- **هدف:** اسکن دوره‌ای کانفیگ‌های مرده (حذف‌شده روی پنل) و ساخت مجدد خودکار.
- **دیتابیس:** بدون تغییر.
- **فایل‌ها:** `cronbot/config_repair.php` (جدید — `DataUser` هر اینوویس فعال را چک می‌کند؛ اگر ۴۰۴ → `createUser` دوباره).
- **جریان:** کرون هر ۶ ساعت `DataUser` می‌گیرد ← کانفیگ گم‌شده را با همان مشخصات بازمی‌سازد ← به ادمین گزارش می‌دهد.
- **اولویت:** 🥈 | **ریسک:** بالا — ساخت دوباره روی پنل با نام تکراری؛ فقط وقتی `DataUser` وجود نداشت.

## F30 — نمایش چندارزی
- **هدف:** نمایش قیمت به تومان + USDT/TON با نرخ لحظه‌ای (`rate_arze` موجود پایه است).
- **دیتابیس:** بدون تغییر.
- **فایل‌ها:** `function.php` (توسعه `rate_arze` + تابع `formatPriceMulti`)، `keyboard.php`.
- **جریان:** کاربر ارز نمایش را از تنظیمات انتخاب می‌کند؛ همه قیمت‌ها با نرخ لحظه‌ای تبدیل می‌شوند.
- **اولویت:** 🥉 | **ریسک:** کم.

## F31 — ضدسواستفاده (Rate limit + شناسه دستگاه)
- **هدف:** جلوگیری از سواستفاده Trial/تخفیف با محدودسازی نرخ و شناسایی دستگاه.
- **دیتابیس:** `user.device_id` + `request_log` (جدول جدید: user, action, ip, at).
- **فایل‌ها:** `function.php` (تابع `rateLimit($user,$action,$max,$window)`)، `index.php` (گارد در Trial/کدهای گیفت).
- **جریان:** هر اکشن حساس قبل از اجرا `rateLimit` را چک می‌کند؛ دستگاه‌های تکراری برای Trial مجاز نیستند.
- **اولویت:** 🥇 | **ریسک:** متوسط.

## F32 — Developer API + مستندات
- **هدف:** API عمومی برای فروش مجدد (ایجاد کاربر/سرویس/فاکتور) با کلید اختصاصی و scope.
- **دیتابیس:** `api_keys` (جدول جدید: key, label, scopes, revoked).
- **فایل‌ها:** `api/v2/*.php` (جدید — لایه جدید بالای `api/`)، `docs/features/api.md` (مستندات)، `api/utils.php` (گسترش `validateToken` با scope).
- **جریان:** فروشنده کلید می‌گیرد ← `Authorization: Bearer <key>` ← اندپوینت‌های v2.
- **اولویت:** 🥈 | **ریسک:** متوسط.

## F33 — عملیات گروهی ادمین (Batch)
- **هدف:** disable/enable/هدیه/پیام گروهی روی انتخاب کاربران (مثل انتخاب‌های `typecustomer_*` موجود).
- **دیتابیس:** بدون تغییر.
- **فایل‌ها:** `admin.php` (گسترش الگوی موجود «پیام گروهی» به اکشن‌های دیگر)، `api/users.php`.
- **جریان:** ادمین فیلتر (همه/مشتری/غیرمشتری/پنل) + اکشن ← تأیید ← اجرا با گزارش.
- **اولویت:** 🥈 | **ریسک:** متوسط — دقیقاً الگوی `getmeesagestatus` با fail-closed.

## F34 — لاگ امنیتی ادمین (Audit log)
- **هدف:** ثبت ورود ادمین‌ها، تغییرات قیمت، حذف کاربر، برداشت/واریز دستی.
- **دیتابیس:** `admin_logs` (جدول جدید: admin, action, target, ip, at).
- **فایل‌ها:** `function.php` (تابع `logAdmin($action,$target)`)، `admin.php` (فراخوانی در نقاط حساس)، `panel/` (نمایش).
- **جریان:** هر اکشن حساس → یک ردیف لاگ → ادمین کل می‌تواند مرور کند.
- **اولویت:** 🥇 | **ریسک:** کم — الزاماً قبل از RBAC (F13).

## F35 — چرخش خودکار بکاپ
- **هدف:** نگهداری N نسخه پشتیبان (مثلاً ۷ روز) به‌جای یک فایل.
- **دیتابیس:** بدون تغییر.
- **فایل‌ها:** `cronbot/backupbot.php` (توسعه — نام فایل با تاریخ + حذف قدیمی‌تر از N روز).
- **جریان:** کرون موجود را توسعه دهید: `backup_YYYY-MM-DD.sql` + cleanup.
- **اولویت:** 🥇 | **ریسک:** کم.

## F36 — برندینگ قابل‌سفارشی
- **هدف:** رنگ، لوگو، نام ربات، متن‌های کلیدی از تنظیمات (بدون کدنویسی).
- **دیتابیس:** ستون‌های `shopSetting` (رنگ/لوگو) — الگوی `Namevalue/Value` موجود.
- **فایل‌ها:** `admin.php` (فرم برندینگ)، `function.php` (تابع `brand()`)، `keyboard.php`/`index.php` (استفاده).
- **جریان:** ادمین لوگو/رنگ/نام را ست می‌کند ← همه پیام‌ها و کیبوردها آن را می‌گیرند.
- **اولویت:** 🥉 | **ریسک:** کم.

## F37 — فروشگاه عمومی (Public shop page)
- **هدف:** صفحه وب عمومی محصولات با لینک پرداخت مستقیم (بدون تلگرام) برای فروش حضوری/تبلیغات.
- **دیتابیس:** بدون تغییر.
- **فایل‌ها:** `api/shop.php` (جدید — لیست محصولات عمومی)، `app/` (صفحه موجود مینی‌اپ قابل استفاده)، `docs/features/api.md`.
- **جریان:** بازدیدکننده صفحه → انتخاب پلن → پرداخت با درگاه موجود → سرویس به حساب تلگرامی که شماره‌اش را داده می‌رسد.
- **اولویت:** 🥈 | **ریسک:** متوسط.

## F38 — درگاه Telegram Stars
- **هدف:** پرداخت با ستاره تلگرام (بدون کارت) — جذب کاربران بین‌المللی.
- **دیتابیس:** بدون تغییر (`Payment_Method='Stars'`).
- **فایل‌ها:** `payment/stars.php` (جدید — الگوی `payment/tronado.php` + `sendInvoice`/`answerPreCheckoutQuery`)، `botapi.php` (متدهای invoice).
- **جریان:** کاربر «خرید با ستاره» → `sendInvoice` → پرداخت → `pre_checkout_query` → `settleOrderOnce` + `DirectPayment`.
- **اولویت:** 🥇 | **ریسک:** متوسط — `stars_auto_rate`/`stars_margin` از قبل در `function.php:2051-2066` هستند!

## F39 — Onboarding wizard ادمین
- **هدف:** راهنمای گام‌به‌گام ست‌آپ (توکن، پنل، درگاه، کانال گزارش) برای ادمین جدید.
- **دیتابیس:** بدون تغییر.
- **فایل‌ها:** `admin.php` (هندلر `setup_`)، `keyboard.php`، `lang/`.
- **جریان:** اولین ورود ادمین → چک‌لیست وضعیت (پنل؟ درگاه؟ کانال؟) → هر آیتم ناقص با دکمه مستقیم.
- **اولویت:** 🥉 | **ریسک:** کم.

## F40 — Status page عمومی
- **هدف:** صفحه عمومی وضعیت پنل‌ها (آپ/داون، لیتنسی) برای شفافیت با کاربران.
- **دیتابیس:** `panel_health_log` (از F12).
- **فایل‌ها:** `sub/status.php` (جدید — خروجی HTML ساده، بدون auth)، `cronbot/panel_monitor.php` (توسعه).
- **جریان:** هر ۱۰ دقیقه کرون سلامت را ثبت می‌کند ← صفحه عمومی از آخرین رکوردها رندر می‌کند.
- **اولویت:** 🥉 | **ریسک:** کم — فقط داده عمومی (نه توکن/آدرس داخلی).
